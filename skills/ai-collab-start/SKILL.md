# AI 协作启动（ai-collab-start）

只做启动判断和路由，不替代开发、发布或审批。接到研发请求先做**本轮通道**判定，不要按「排查 / 工作量」开完整流水线。

## 续作恢复优先

先判断用户是否指向已有任务：出现任务编号、任务链接、目录名，或“继续 / 接着 / 这个需求 / 合并整改”等上下文词时，按续作候选处理。续作候选必须先按“版本 INDEX → 事实 issue 扫描 → 唯一任务目录 → 任务 INDEX → `00-需求概览.md`”恢复当前阶段、全部 workstreams、唯一 `next.skill`、阻塞项、正式设计指纹和仍有效的限域授权；只在需要审计、证据冲突或历史恢复时读取 trace 片段。

唯一任务匹配后：

- 先以快照的 `next.skill` 路由，不能因用户本轮用了“改/合并/修复”等动作词重置为 `analyze-requirement`、新建任务或重新设计。
- 先判断本轮范围是否仍在快照授权内。范围、风险和授权没有变化时，沿用有效的风险确认和授权，直接交给快照指定 Skill；只有范围扩大、风险升级、授权缺失/撤销或当前证据失效，才补风险卡或回对应门控。
- 旧指纹没有 `hash_version`、版本未知或工具无法计算时，保留原阶段与 `next.skill`，只阻断依赖该指纹的动作并转证据恢复；不能把它直接判作正文变化、重开访谈或重做无关设计。

没有唯一匹配时不得猜目录：没有候选才按新需求入口处理；多个候选或路径损坏时保持 `waiting-user`，只询问任务归属。

## 本轮通道

只看**这一轮是否只读、不落盘、不改系统**，不看话题词。每条用户新消息都重新判定。

**轻量**（须同时满足）：本轮不写文件、不改配置、不跑改环境命令、不调生产系统、不建档/issue；意图是解释、只读定位、列假设、口头估工或对比但不落盘；不是在答访谈 `Qn`，也不是快照要求继续的阶段动作。

轻量只做：标「本轮轻量 / R0 只读」、直接回答、一句「未进入任务档案」。不扫 INDEX/issue、不出进度卡、不访谈、不等风险确认、不转下游 Skill。

**完整**（命中任一）：要改代码/配置或跑改环境命令；要建档、写 01/02/03/03A、issue、worklog；用户要修/落地/进方案/实施；生产、真机、真数据、证书、批量或升级规则至少 R3；活跃访谈或快照 `next.skill` 未结束。

不确定：先轻量回答，并问是否立项或改代码。

### 升级到完整通道

识别**用户要动手或立项**则当轮升级，不得继续标轻量，更不得在轻量里改文件。看用意：修掉、帮我改、落地、按你说的改、建档、进方案、授权写文件。

不升级：AI 自己说「这里需要改」（只问「要转入工作流吗？」）；「可能要改」而没让现在改；只要原因或估工。

升级当轮：

1. 告知已转入完整工作流。
2. 若为续作，先按“续作恢复优先”读取并播报当前快照；把已查原因、位置、假设收成短清单，不从零再问。
3. 仅新需求或续作范围/风险/授权发生变化时，评风险并出风险卡；同轮不改文件、不跑命令。范围未变的续作沿用有效确认，直接进入快照指定 Skill。
4. `next_step`：有快照则严格恢复 `next.skill`；否则默认 `analyze-requirement`。只要「立刻改这一处」且范围已收窄，仍需先确认本轮范围与授权再转 `implement-change`。
5. 范围比已确认扩大、证据失效或授权变化：重新出卡并只转对应门控。

## 工作流程（仅完整通道）

0. 通道分流；轻量且未升级则结束。
1. 续作候选先按“续作恢复优先”定位并读取快照；新需求再组 `task_card`。
2. 内部组 `task_card`（含主 `product`、`product_touchpoints[]`、目标/本轮风险、协作模式）。
3. 加载已登记适配器；未登记、`catalog-only` 或 `missing_evidence` 则 fail-closed，不猜仓库或风险。`common` 不自动带 项目专用 风险。`blocked-in-this-repo` 可分析设计，不路由实施。
4. 仅在新需求或续作范围/风险/授权变化时，取通用模型与全部适配器 `risk_triggers[]` 最高值并出风险卡；适配器只能升高。
5. 活跃 `requirement_interview` 优先：`continue-interview` / `ready-for-confirmation` 只许 `analyze-requirement`；`Qn` 不是建档或结束指令。仅 `ready-to-draft` 或无需访谈才可 `init-project-docs` / `write-plan` / 方案 / 决策卡。
6. 新需求默认 `analyze-requirement`；续作严格使用快照唯一 `next.skill`。完整字段见 `../write-plan/references/stage-handoff.md`。
7. 多 `workstreams` 时播报全部子流；进度卡前先扫 issue 事实源（open/closing 与协调文件），README 只是派生索引。任务级 `next.skill` 只是本轮优先，不能遮住其他等待项或活动 issue。
8. 输出摘要、风险卡（仅需要时）、最多 3 问和下一步。不得在本 Skill 比较实现方案或写「确认后实施」。

## 输出

- 轻量：回答 +「本轮轻量 / R0 只读，未进入任务档案」。
- 完整：可读摘要 + 行动前风险卡 + 最多 3 张路由/授权问题卡。不默认展示 YAML、证据路径、`confirmed_facts`。
- 导出 YAML 仅当用户明确要求；读 `references/task-card-export.md`。
- 用户可用自然语言或 `Q1：...` 回答；不声称有按钮或下拉框。
- reason 不超过 30 字。不展开完整决策卡/任务档案，除非用户要求展开。

## 风险与协作

| 等级 | 定义 | 模式与动作 |
|---|---|---|
| R0 | 只读问答、解释、查询 | AI 自动处理；摘要标 R0，可直接答 |
| R1 | 文档、小配置、低风险小改 | AI 自动处理；风险卡确认后可改，必要时 trace |
| R2 | 普通业务代码 | AI 辅助开发；风险卡确认后建/复用 plan，人 review |
| R3 | 数据、权限、外部接口、设备侧 | AI 辅助决策；先决策卡 |
| R4 | 生产、批量、不可逆、证书密钥、计费、生产批量操作 | 人主导；只辅助方案、回滚、停止线 |
| R2-R4 排障 | 缩小范围 | 协作排障；必要时 issue |

升级：生产至少 R3；生产数据写/删、证书密钥、计费、生产批量操作为 R4；生产状态机、外部服务接口至少 R3；不可回滚或回滚未验证至少 R3。

本轮只做沙盘/不改文件：协作模式多为 `AI辅助决策`，目标风险仍可是 R3/R4，本轮风险用 R0/R1。R3/R4 默认要决策卡，沙盘不展开全文。`interview_finish_mode` 默认 `confirm`；仅用户要求自动结束且目标 R0-R2 才可 `auto`。

R3+ 或安全/计费/证书/设备侧、结论不确定、用户要求复核：可用 subagent，无审批权。

## 行动前风险展示

仅完整通道且将行动。不是决策卡；R1/R2 不必写 `03`。短卡（不要 YAML）：目标/本轮风险、协作模式、范围、一句依据、请确认继续 / 纠正 / 缩小 / 停止。

- 出卡后停一轮；同轮不改文件、不跑命令。
- 确认或纠正后再确认：才交实施类 Skill。
- 纠正更高：采用。纠正更低：升级规则仍生效，冲突则 `waiting-user`。
- 制止或未回复：不行动。「改成 X / 直接做」不能代替本卡确认。
- 范围扩大：重新出卡。
- 多 issue / 多 workstream 共用一张卡时，必须并列各 ID，并写出每项范围、本轮风险上限、回滚/停止线（若适用）。一句「这几单一起做」不能省略分项；批准只覆盖卡上列出的 ID。这不是决策卡，也不另造合并决策产物。

## 入口问题边界

只问阻塞路由或授权的问题，最多 3 个：产品/复用任务、读写授权、是否转入工作流、风险或范围纠正、是否生产/真机/真数据、ticket 归属。

禁止问（留给勘察后的需求或方案）：校验松紧、`@NotNull` / `@Valid`、防重放/鉴权算法、方案 A/B、类名注解配置键、「确认后实施」。

未见现状不得让用户拍实现走向。完整通道的真实需求/安全清单下一跳是 `analyze-requirement`。尚未勘察就说「直接做」：仍转需求分析。

## 下游路由

轻量不转下游。升级后：默认 `analyze-requirement`（复用排查事实）；有快照跟 `next.skill`；范围收窄且风险卡已确认才可 `implement-change`。

完整通道：方案 → `design-solution`；R3/R4 拍板 → `make-decision-card`；建档 → `write-plan`；实施 → `implement-change`（按适配器挂模块 UI，使用通用单测）；验证 → `verify-delivery`（挂通用审查和项目 UI 走查）；trace / worklog / issue 用对应 Skill。

已发布设计：路由前调用 [统一指纹工具](../aggregate-design/references/fingerprint-tool.md) 从当前文件核 freshness（来源 hash、source-set、03A 第 1～11 章）。不匹配则转 `check-design` / `aggregate-design` / `design-solution`，不猜、不沿用快照旧等式。无版本、未知版本、缺文件或解析失败只进入证据恢复，保留原阶段和 `next.skill`，不直接判正文变化。`check_status` 非法则 fail-closed。需设计的 workstream 必须被 artifact `workstream_ids` 覆盖。整合评审说法按快照：`stale`→自检，`waiting-review`→聚合，`change_target=source|aggregation` 才回流，缺失则 `waiting-user`。细则在对应设计 Skill。

`blocked-in-this-repo` / `catalog-only` 不实施。仅经批准、限域、未过期的 `bootstrap_exception` 可临时绕过自举门。03A 批准后实施默认读任务 INDEX、`00`、已批准 03A。

## 关键要求

- 先判断是否续作并恢复快照，再决定通道与路由；只读排查/估工不开全套。
- 新需求或范围变化要升级并出风险卡；同范围续作沿用有效确认。AI 建议修改不得自行升级。
- 完整通道在范围/风险/授权变化时先展示风险再行动；同范围续作沿用有效确认，同轮不得边评边改。
- 续作不得因通用动作词重新需求分析或创建新档案；只有没有唯一匹配、快照冲突、证据失效或范围变化才回流。
- 高风险先决策卡；决策批准 ≠ 实施授权。
- `next.skill` 非 `none` 不得写任务完成。本 Skill 不替代下游归档 Skill。
- 精简或大幅改写本 Skill 正文前，先把当前版复制到 `backups/SKILL-{version}.md`；已有同名不覆盖。
