# 单元测试

## 触发

- 本轮修改了业务行为，存在需要验证的边界或回归风险。
- 用户要求补测试、复现问题或执行测试。

纯文档、生成代码和低影响可逆调整通常无需新增测试。

## 工作步骤

1. 读取项目测试配置和同模块现有用例，确定测试目录、命令及运行环境；Java 项目可参考 `references/java-test-baseline.md`。
2. 对照验收标准与 diff，使用 `references/case-checklist.md` 选择关键行为、异常与边界；适用时读取产品的 `unit_test_extras[]`。
3. 新增或修改最小必要用例，不覆盖无关测试，不为了测试引入新框架。
4. 在已授权范围内执行对应测试。授权已覆盖测试时无需重复确认。
5. 记录实际命令、退出码、通过与失败项；未运行时说明原因，不写成通过。

## 边界

- 遵循当前模块语言版本与测试约定。
- 单元测试隔离真实外部 I/O；集成测试按项目单独配置的环境和范围执行。
- 不设置统一行覆盖率门槛；重点验证验收行为。
- 不编写只镜像实现的断言，不重复运行已成功且未受后续修改影响的整套测试。
- 审查交给 `code-review`；完成后返回 `implement-change` / `verify-delivery`。
